# 면접 재연결 (FE)

> **스토리**: HBB1-308 — 나는 사용자로서 연결이 끊겨도 면접을 이어갈 수 있다.
>
> **원천 문서**: 재연결 계약(세션 INTERRUPTED 유지·재입장 토큰·유예 만료 ABORTED)의 원천은 Kkori-Backend 재연결 PRD — **확정 대기 중**이며, 서버 상태 머신·창 길이·TTL은 그 문서가 정의하고 **이 문서는 FE 화면 동작만** 정의한다.
>
> **계약 상태**: 재입장 토큰 API는 **미확정**(경로·응답·에러 코드·창 길이 전부) — FE는 손코딩 목으로 선행 구현하고, 스펙 확정 시 client 함수 본문만 orval 생성물로 교체한다. 미확정 값(시도 횟수·간격·거부 코드)은 전용 상수로 격리한다. `ROOM_DELETED = 면접 종료`는 기존 확정 계약 그대로다.

## Overview

지금까지 ROOM_DELETED가 아닌 연결 해제는 "연결 끊김" 표시로 방치됐다(HBB1-294에서 후속 스토리로 명시). 이번 스토리는 그 공백을 3계층 복구로 채운다 — (1) livekit 자동 재연결은 비차단 표시로 통과시키고, (2) 자동 재연결이 포기하면 재입장 토큰으로 같은 룸에 다시 들어가며, (3) 새로고침으로 토큰이 만료된 재진입도 같은 재입장 경로가 받는다. 면접 시계는 끊김 중에도 계속 흐른다(서버 확정) — 프론트는 시간을 모르므로 안내 문구 수준으로만 다룬다.

```text
연결 요동 ──▶ Reconnecting/SignalReconnecting ──성공──▶ Connected (원상 복귀)
    │             └─ 필 "재연결 중…" — 비차단 (마이크는 기존 로직으로 잠김, 종료 버튼 유지)
    └─포기──▶ Disconnected(사유 ≠ ROOM_DELETED) ──▶ 전면 오버레이 "다시 연결하는 중"
                  ├─ 자동 재입장 (즉시·4초·10초, 매회 새 토큰, 단일 진행) ──성공──▶ 재접속·마이크 복원
                  ├─ 소진 ──▶ 수동 "다시 연결"만 (클릭 = 남은 자동 일정 취소 후 1회 시도)
                  ├─ "이미 종료" 거부 ──▶ 저장값 정리 → /live/ended (부제: 이미 종료 — 중립)
                  └─ "면접 종료" 버튼 ──▶ 기존 /end 경로 — 202·S008 = 종료 수렴 (연결 없는 종료 확장)
새로고침(/live 재진입) ──▶ 저장 토큰 접속 시도 ──실패──▶ 재입장 폴백 (위 오버레이와 동일 수렴)
ROOM_DELETED ──▶ 기존 종료 경로 그대로 — 재입장을 시도하지 않는다
```

### 기능 요구사항

| No. | Function        | Description                                                                                                    |
| --- | --------------- | -------------------------------------------------------------------------------------------------------------- |
| 1   | 자동 재연결 표시 | Reconnecting 계열 상태에서 비차단 "재연결 중" 표시를 유지하고, 성공(Reconnected) 시 원상 복귀한다.                 |
| 2   | 재입장          | ROOM_DELETED가 아닌 Disconnected에서 재입장 토큰을 받아 같은 룸에 재접속한다 — 자동 3회 + 수동, 단일 진행.          |
| 3   | 새로고침 복원   | 저장 토큰 접속 실패 시 저장된 세션 id로 재입장 토큰을 받아 접속한다 — 새로고침 생존을 겸한다.                       |
| 4   | 이미 종료 안내  | 재입장이 "이미 종료된 세션"으로 거부되면 종료 화면으로 수렴하고 중립 부제로 안내한다(창 소진 세분화는 BE 코드 확정 후). |

## 자동 재연결 (livekit 소관)

### 설명

- livekit-client가 일시 끊김을 자동 재연결한다 — `ConnectionState.Reconnecting`/`SignalReconnecting`으로 노출되며, 기존 상태 필("재연결 중…", 파란 점)을 유지한다. **비차단** — 전면 오버레이를 띄우지 않는다(순간 회복이 흔해 깜빡임이 된다).
- 조작 잠금은 기존 로직 그대로: 마이크 토글은 Connected가 아니면 이미 비활성. **종료 버튼은 활성 유지** — `/end`는 HTTP 호출이라 룸 연결 없이 동작하고, 202 후 연결 없음 수렴(HBB1-294)이 받아준다.
- Reconnected 시 별도 처리 없음 — 자동 재연결은 SDK가 기존 로컬 트랙을 복구하므로(완전 재입장과 다름) 상태 필이 "연결됨"으로 돌아오는 것으로 끝난다.

### 검증 기준

- Reconnecting 계열 상태에서 필 라벨이 "재연결 중…"으로 표시되고 전면 오버레이가 뜨지 않는지 확인
- 재연결 중 종료 버튼이 활성 상태로 동작하는지 확인

## 재입장

### 설명

- **트리거**: `Disconnected` + `disconnectReason ≠ ROOM_DELETED` + 종료 미확정. ROOM_DELETED는 기존 종료 수렴이, /end 202 후 연결 없음은 기존 연결 없는 종료 수렴이 **우선**한다 — 이 두 경우 재입장을 시도하지 않는다.
- **종료 요청과의 상호배제**: 종료 요청 **발신 시점부터 결과 도착까지 재입장을 일시 중단**한다(예약 타이머 정지·수동 버튼 비활성). 결과별 — **202와 S008은 모두 종료 확정으로 저장값을 정리하고 종료 화면으로 수렴**한다. 둘 다 종료 의도가 서버에 기록되어 fallback이 최대 180초 내 terminal 수렴을 보장하는데, 연결이 없어 이후 ROOM_DELETED를 관찰할 수 없으므로 기다릴 신호가 없다 — HBB1-294의 "연결 없는 종료" 수렴(202 한정)을 **S008로 확장**한다(연결이 살아 있는 S008은 기존 지연 안내 + 재시도 그대로). **그 외 실패는 종료가 성립하지 않은 것 — 재입장을 재개**한다. 일시 중단 시점에 진행 중이던 토큰 발급의 늦은 응답은 폐기한다(접속에 사용하지 않는다).
- **전면 오버레이**: "연결이 끊겼어요 — 다시 연결하는 중" + 진행 표시 + "면접 시간은 계속 진행되고 있어요" 한 줄(**창 길이 숫자는 미노출** — 미확정 값). 하단에 수동 "다시 연결" 버튼과 "면접 종료" 버튼. 그 외 조작은 오버레이가 가린다.
- **자동 시도**: 3회 — 즉시·4초·10초(상수 격리). 매 시도마다 재입장 토큰을 **새로 발급**받아 `room.connect`한다(발급~접속 사이 만료 레이스 방지). 토큰 API 자체가 실패(네트워크 등)해도 시도 1회를 소모한다. 소진 후에는 수동 버튼만 남기고 "연결하지 못했어요 — 네트워크를 확인한 뒤 다시 시도해 주세요" 안내를 표시한다.
- **동시성 — 시도는 한 번에 하나**: 진행 중에는 수동 버튼을 비활성("연결 중…")한다. 수동 클릭은 남은 자동 일정을 취소하고 즉시 1회 시도하며, 이후는 수동 전용이다. 성공·종료 확정(202/S008)·ROOM_DELETED 도착·화면 이탈 시 예약 타이머를 모두 취소하고, 이미 발신된 요청의 늦은 응답은 폐기한다(시도 세대 기준).
- **재입장 API**(미확정 — 목): 세션 id로 같은 identity의 새 토큰을 재발급받는다. 목은 `{ url, token, room }` 응답과 "이미 종료" 거부(placeholder 코드)를 재현한다.
- **성공 처리 순서**: ① 발급 응답 수신 시 인증 세션 재대조(발급 사이 계정 교체 감지 — 불일치면 응답 폐기, 기존 게이트 경로) → ② 활성 세션을 **메모리(React 상태)에서 새 토큰으로 교체**해 재접속한다 — 현재 화면은 저장값을 마운트 시 고정하므로 상태 교체가 실접속의 원천이다 → ③ 접속 성공 확인 후 id·authSessionId를 보존한 채 저장값(`hbb.interview.session`)을 갱신한다(실패한 토큰은 저장하지 않는다) → ④ 오버레이를 닫는다. 저장 갱신이 실패해도(쿼터 등) 접속 성공이 원천이므로 오버레이를 닫고 면접을 계속한다 — 기존 레코드(구 토큰·동일 id)가 남아 있어 이후 새로고침은 재입장 폴백으로 복구된다.
- **마이크 복원**: 완전 해제는 로컬 트랙을 unpublish한다(SDK 동작 — 자동 재연결과 다름). 재접속만으로 음성이 복구되지 않으므로 **마이크 의도 상태(micIntent)를 SDK 실제 발행 상태와 분리해 관리**한다 — 성공한 사용자 토글과 성공한 복원 재발행 때만 갱신하고, **연결 해제 과정에서 SDK가 내린 꺼짐은 기록하지 않는다**. 재입장 성공 시 micIntent가 켜짐이면 자동 재발행하고, 실패하면 기존 마이크 안내(micFailed)로 떨어뜨린다. micIntent는 세션 저장값에 함께 기록해 새로고침 경로도 같은 규칙을 따른다 — 필드가 없는 구레코드의 기본값은 **꺼짐**(예상 밖 자동 발행 방지, 현행 /live 초기 동작과 동일).

### 검증 기준

- ROOM_DELETED가 아닌 Disconnected에서 오버레이가 뜨고 재입장 토큰 발급 → 재접속이 자동 시도되는지 확인
- ROOM_DELETED 해제는 재입장 시도 없이 기존 종료 화면 전환이 유지되는지 확인 (기존 계약 회귀)
- 종료 요청 발신 중 재입장이 멈추고, 202·S008은 저장값 정리 후 종료 화면으로 수렴하며, 그 외 실패 후에만 재개되는지 확인
- 수동 클릭이 남은 자동 일정을 취소하고 단일 시도만 진행하는지, 시도 진행 중 수동 버튼이 비활성인지 확인
- 자동 시도 소진 후 수동 버튼만 남고, 수동 클릭이 새 토큰 발급부터 다시 시도하는지 확인
- 재입장 성공 시 저장값 갱신이 접속 성공 후에 일어나고(id·authSessionId 보존), micIntent가 켜짐이면 자동 재발행되는지 확인
- 연결 해제로 SDK 발행 상태가 꺼진 것이 micIntent·저장값에 기록되지 않는지 확인
- 재입장 성공 후 이전 disconnectReason이 남아 있어도 재입장이 다시 발화하지 않는지 확인
- 토큰 A에서 마이크를 복원한 뒤 토큰 B 재입장에서도 복원이 다시 1회 실행되는지 확인
- 오버레이의 "면접 종료"가 기존 /end 경로(202 + 연결 없음 수렴)로 완료 화면에 도달하는지 확인

## 새로고침 복원

### 설명

- `/live` 재진입(새로고침) 시 기존 게이트(저장값 존재 + 인증 세션 일치)는 그대로다. 저장 토큰으로 먼저 접속을 시도하고 — TTL 단축(~3분)으로 만료됐을 수 있다 — **접속 실패(`connectError`) 시 재입장 폴백**으로 넘어간다. 현재 "접속 실패" 데드엔드 지점이 재입장 오버레이로 대체된다.
- 저장 토큰 우선(항상 재발급 대안 대비): 핸드오프 직후·짧은 새로고침에서 불필요한 발급 호출을 피하고, 실패 시에만 폴백한다.
- 폴백 이후의 시도·소진·거부 처리는 위 재입장과 동일하다(경로 합류). 마이크 복원은 폴백 여부와 무관하다 — **저장 토큰으로 바로 접속에 성공한 경우도 완전 새 입장이라 트랙이 없으므로**, 저장된 micIntent를 동일 규칙으로 복원한다.

### 검증 기준

- 저장 토큰 접속 실패 시 재입장 폴백이 발동해 새 토큰으로 접속하는지 확인
- 폴백의 "이미 종료" 거부가 이미 종료 안내로 수렴하는지 확인
- 폴백 없이 저장 토큰으로 바로 접속한 새로고침에서도 저장된 micIntent가 복원되는지 확인

## 이미 종료 안내

### 설명

- 재입장 거부("이미 종료된 세션")는 창 소진(유예 만료 ABORTED)뿐 아니라 **모든 terminal 상태에서 나올 수 있다** — 정상 완료 직후의 새로고침, 다른 경로로 종료된 세션 등. 따라서 거부 코드가 사유를 구분해 주기 전까지는 **중립 부제**로 안내한다: "이미 종료된 면접이에요" 류. 창 소진을 단정하는 문구("시간이 지나 종료되었어요")는 쓰지 않는다.
- 수렴 형태: 저장값을 정리하고 `/live/ended`로 replace 이동, 이동 state는 `{ ended: true, reason: "reentry-denied" }`. 제목("면접이 끝났어요")과 대시보드 이동 버튼은 공용, 부제만 분기한다.
- **BE 확정 대기 2건**: ① 거부 코드가 창 소진(REENTRY_WINDOW_EXPIRED류)을 구분해 주면 그 경우에 한해 창 소진 문구로 세분화한다. ② ABORTED 세션의 리포트 생성 여부가 확정되기 전에는 이 부제에 리포트를 언급하지 않는다.

### 검증 기준

- 재입장 거부 수렴 시 종료 화면 제목은 동일하고 부제가 중립 안내로 분기되는지 확인
- 정상 종료(ROOM_DELETED) 경로의 기존 화면·문구가 변하지 않는지 확인

## 인터페이스 요구사항

- 클라이언트: `src/api/client.ts` — `reenterInterviewSession(sessionId)` 손코딩 목(지연 + 성공/거부 재현). BE 스펙 확정 시 `pnpm orval` 재생성물 위임으로 본문 교체. 훅: `src/api/hooks.ts` — `useReenterInterviewSession`(useMutation)
- 상수 격리: 재입장 시도 횟수·간격, "이미 종료" 거부 코드 placeholder — 미확정 값 전용 상수 모듈(확정 시 이 파일만 갱신)
- 활성 세션: `src/pages/InterviewPage.tsx` — 마운트 고정 `stored`를 **활성 세션 React 상태(초기값 = 저장값)**로 바꾸고, 재입장 성공 시 상태 교체가 재접속의 원천이 되게 한다
- 재입장 오케스트레이션: 단일 진행·타이머 취소·세대 기준 늦은 응답 폐기를 전용 훅으로 캡슐화(페이지는 상태만 소비)
- 세션 저장값: `src/hooks/interviewSession.ts` — 마이크 의도(micIntent) 필드 추가(하위호환 — 없으면 꺼짐)
- 연결 없는 종료 수렴: `src/pages/InterviewPage.tsx` — 기존 202(isSuccess) 한정 조건을 S008 에러까지 확장 (HBB1-294 문서의 해당 절은 본 문서가 갱신)
- LiveKit: `src/hooks/useLiveKitRoom.ts` — 세션 교체 시 기존 Room 재사용·재접속(기존 구조). 재입장 성공 후 이전 `disconnectReason` 잔존이 판정을 오염하지 않도록 트리거는 다음 조건식으로 고정한다 — `connectionState === Disconnected && (connectError !== null || (disconnectReason !== null && disconnectReason !== ROOM_DELETED))`. 최초 마운트(사유 null·접속 전)는 자연 제외되고, 오버레이 표시는 이 트리거와 시도 진행 메타데이터에서 파생한다. 마이크 복원은 토글 재사용이 아닌 명시적 켜기 API로, 토큰(시도 세대)당 1회 가드
- 종료 화면: `src/pages/InterviewEndedPage.tsx` — 이동 state `reason` 확장, 부제 분기

## 제약사항·범위 외

- 백엔드 재입장 API·TTL 단축·유예 만료 ABORTED와 AI의 맥락 복원은 병행 세션 소관 — FE는 목으로 선행하고 신호만 소비한다.
- 면접관 소실(AGENT_LOST)의 FE 안내는 범위 외 — 사용자에겐 잠시 침묵 후 복귀로 보이며 별도 UI 없음.
- 남은 시간 실표시는 범위 외(서버 기준시 부재 — HBB1-294에서 제거된 타이머와 동일 사유). 오버레이의 "시간이 계속 진행" 문구까지만.
