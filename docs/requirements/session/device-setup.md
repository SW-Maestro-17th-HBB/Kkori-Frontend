# 면접 전 장비 점검 (FE)

> **스토리**: HBB1-19 — 나는 사용자로서 면접을 원활히 보기 위해 시작 전 마이크·카메라를 연결할 수 있다.
>
> **하위 이슈**: HBB1-144 [개발] 면접 시작 전 설정 확인 개발 · HBB1-145 [테스트] 면접 시작 전 설정 테스트
>
> **원천 문서**: `docs/drafts/design-handoff.md` §6-④ (setup 화면 카메라·마이크 점검 UI) · `docs/drafts/interview.md` §2 (미디어 평면 — 면접 중 Agent로 전송되는 미디어는 **오디오뿐**, 카메라는 로컬 self-view 용). 이 문서는 **FE 화면 동작만** 정의한다.
>
> **범위**: `/setup` ④ 장비 점검과 **선택한 마이크의 `/live` 핸드오프**(`useLiveKitRoom` 캡처 기본값 적용 포함). ①이력서 선택 ②면접 유형 ③면접 시간은 HBB1-18 범위이고, 면접 중 카메라 self-view·카메라 publish는 제외한다.

## Overview

면접 설정 화면(`/setup`) ④단계의 장비 점검 흐름을 정의한다. 모든 기능은 React SPA(브라우저)에서 실행되며, LiveKit 룸에 연결하지 않은 로컬 전용 상태에서 마이크·카메라 트랙을 미리 획득해 미리보기·레벨 미터·장치 선택을 제공한다. **마이크는 면접 시작의 필수 조건이고 카메라는 선택**이다(없으면 경고 후 음성 진행). 점검에서 고른 장치는 면접 화면(`/live`)의 마이크 캡처 설정으로 이어진다.

```text
/setup ④ ── "장비 점검 시작" 버튼 또는 카메라·마이크 드롭다운 클릭 ──▶ 마이크+카메라 동시 권한 요청
    ├─ 성공: self-view(프레임 도착 확인)·레벨 바·장치 드롭다운 목록 채움
    │      └─ 마이크 입력 감지(말하기) → "마이크 정상" 확정 → "면접 시작" 활성
    ├─ 결합 요청 실패(원인 무관): 마이크 단독 재확인
    │      ├─ 성공: "카메라 사용 불가" 경고 → 입력 감지 후 "면접 시작" 활성 (음성 진행)
    │      └─ 실패: 원인별 안내(권한 거부 · 마이크 없음 · 접근 불가 · 환경 미지원 · 기타) + "다시 시도"
    └─ 점검 완료 후 장치 상실: 마이크 → 기본 장치 자동 전환(없으면 점검 무효화), 카메라 → 경고 전환
"면접 시작" ── 선택 마이크 저장(sessionStorage) ──▶ /live (Room 생성 시 저장된 마이크 적용)
```

### 기능 요구사항

| No. | Function               | Description                                                                                                        |
| --- | ---------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 1   | 장비 점검 시작         | "장비 점검 시작" 버튼 클릭으로 마이크(필수)·카메라(선택) 권한을 요청해 로컬 트랙을 획득하고, 실패 원인별 안내·재시도를 제공한다. |
| 2   | 미리보기·상태 표시     | 카메라를 self-view로 미러 표시하고, 마이크 입력 레벨 바와 정상 확인 3종(카메라·마이크·권한) 칩을 실제 상태로 구동한다.       |
| 3   | 장치 선택·전환·상실 처리 | 연결된 카메라·마이크 목록을 표시하고 선택 시 전환하며, 전환 실패와 사용 중 장치 상실(제거) 시의 동작을 정의한다.              |
| 4   | 면접 시작 게이팅·핸드오프 | 마이크 점검 완료 전 "면접 시작"을 비활성화하고, 시작 시 선택 장치를 저장해 면접 화면(/live)의 마이크 캡처에 적용한다.        |

## 장비 점검 시작

### 설명

④ 카드의 초기 상태는 점검 전 — self-view 자리 표시, "장비 점검 시작" 버튼, 그리고 **처음부터 활성화된 카메라·마이크 드롭다운**을 노출한다. **버튼 클릭 또는 드롭다운 클릭**(모두 사용자 제스처) 시 장치 권한을 요청하고 로컬 트랙을 획득한다 — 특정 장치부터 고르고 싶은 사용자가 드롭다운에서 막히지 않게 하기 위함이다.

- 마이크+카메라를 **동시에 요청**해 가능한 경우 권한 프롬프트를 통합한다. 결합 요청이 **원인과 무관하게** 실패하면(카메라 권한만 거부·카메라만 점유 중인 경우 포함) **마이크 단독으로 재확인**한다 — 카메라는 선택 사항이므로 카메라 문제가 마이크 점검을 막아서는 안 된다. 이 재확인 때문에 **권한 프롬프트 1회는 항상 보장되지 않는다**.
- 마이크 단독 확인이 성공하면 "카메라 사용 불가" 경고와 함께 음성 진행 모드로 전환한다(면접 시작 허용).
- **마이크는 필수** — 마이크 단독 확인까지 실패하면 점검 실패 상태가 되며, 실패 안내는 마이크 단독 시도의 원인을 기준으로 표시한다.
- 실패 원인 분류(DOMException.name 매핑)와 안내:
  - 권한 거부(`permission-denied`: NotAllowedError) — 브라우저 권한 해제 방법 안내
  - 마이크 없음(`mic-not-found`: NotFoundError·OverconstrainedError) — 마이크 연결 안내
  - 접근 불가(`device-in-use`: NotReadableError·AbortError) — 원인을 단정하지 않는 문구: "다른 앱에서 장치를 사용 중이거나 장치에 접근할 수 없어요"
  - 환경 미지원(`unsupported`: SecurityError·`mediaDevices` API 부재) — HTTPS(secure context)·지원 브라우저 안내 (사용자 권한 거부와 구분)
  - 기타(`unknown`) — 일반 재시도 안내
  - 모든 실패 상태에 "다시 시도" 버튼을 제공한다.
- 획득한 트랙은 **로컬 전용**(룸 publish 없음)이며, 페이지 이탈(언마운트) 시 해제한다 — 면접 화면이 장치를 다시 획득한다.

### 실행 조건

- secure context(HTTPS 또는 localhost) — getUserMedia 동작 조건.
- 권한 요청은 사용자 제스처(버튼 클릭) 안에서 시작한다 — 진입 즉시 자동 요청하지 않는다.

### 검증 기준

- 점검 시작 클릭 시 권한 프롬프트가 뜨고, 허용하면 점검 완료 상태가 되는지 확인
- 카메라·마이크 드롭다운 클릭으로도 점검이 시작되는지 확인
- 권한 거부 시 해제 방법 안내와 "다시 시도" 수단이 표시되고, 허용 후 재시도로 복구되는지 확인
- 카메라가 없는 기기에서 마이크만으로 점검이 완료되고 경고가 표시되는지 확인
- **카메라 권한만 거부하거나 카메라만 점유 중이어도** 마이크가 정상이면 음성 진행으로 점검이 완료되는지 확인
- 마이크 접근 불가 시 원인을 단정하지 않는 안내("사용 중이거나 접근할 수 없음")가 표시되는지 확인
- 비보안 컨텍스트·미지원 브라우저에서 권한 거부와 구분된 환경 안내가 표시되는지 확인
- 페이지 이탈 시 장치가 해제되는지(브라우저 탭의 카메라·마이크 사용 표시가 꺼지는지) 확인

### 성능 요구사항

- 없음 (권한 요청·획득 중에는 "장비 연결 중" 상태를 표시한다)

### 인터페이스 요구사항

- 라우트: `/setup` ④단계 (`src/routes.ts` — 기존 라우트, 신규 없음)
- 훅: `src/hooks/useDeviceSetup.ts` — 화면은 이 훅만 쓰고 SDK를 직접 만지지 않는다 (`useLiveKitRoom` 패턴과 동일)
- SDK: `livekit-client`의 `createLocalTracks` (`/live`와 동일 SDK 경로 — 별도 raw getUserMedia 래퍼를 만들지 않는다)

### 제약사항

- 점검 단계에서는 LiveKit 룸에 연결하지 않는다 — 토큰·세션 불필요.
- 트랙을 publish하지 않는다.

### 기타 요구사항

- 없음

## 미리보기·상태 표시

### 설명

획득한 트랙을 사용자가 눈으로 확인할 수 있게 표시한다.

- **self-view**: 카메라 트랙을 다크 박스에 미러(scaleX(-1))로 표시한다. 카메라가 없으면 "카메라 없음 · 음성으로 진행" 안내를 유지한다.
- **마이크 정상 판정 — 실입력 감지**: 트랙 획득만으로는 정상으로 표시하지 않는다(OS 음소거·무신호 장치 배제). 획득 후 칩은 **"마이크 입력 대기"** 상태가 되고 "마이크에 대고 말해보세요" 안내를 표시하며, 레벨이 임계치를 한 번 넘으면 **"마이크 정상"** 으로 확정한다. 임계치는 구현 상수로 두고 실측 조정한다. **장치 전환·자동 전환 후에는 입력을 다시 확인**한다(새 장치는 미검증 상태).
- **카메라 정상 판정 — 실프레임 확인**: 카메라 칩은 트랙 획득이 아니라 self-view 비디오에 **실제 프레임이 도착**(재생 시작)한 뒤 "카메라 정상"으로 표시한다. 프레임 도착 전에는 "카메라 확인 중"으로 둔다.
- **마이크 레벨 바**: 마이크 입력 레벨을 기존 7-bar UI로 실시간(120ms 주기) 표시한다. 시각 피드백이자 위 실입력 감지의 판정 신호다.
- **정상 확인 3종 칩**: 카메라 · 마이크 · 마이크 권한. 권한 칩 문구는 **"마이크 권한 허용됨"** — 카메라는 선택 사항이므로 권한 칩은 필수 권한(마이크)만 뜻한다. 상태는 확인 전(중립) / 확인 중·입력 대기(중립) / 정상(체크) / 차단·없음(경고)이며 실제 점검 상태에서 파생한다.

### 실행 조건

- 장비 점검 시작(기능 1) 성공이 선행되어야 한다.

### 검증 기준

- 점검 완료 시 내 모습이 미러로 표시되는지 확인
- 마이크에 말하면 레벨 바가 반응하는지 확인
- 말하기 전에는 마이크 칩이 "입력 대기"이고 "말해보세요" 안내가 표시되는지 확인
- 말해서 레벨이 임계치를 넘으면 "마이크 정상"으로 확정되는지 확인
- 카메라 칩이 실제 프레임 도착 후에만 "카메라 정상"이 되는지 확인
- 장치 전환·자동 전환 후 마이크 입력을 다시 확인하는지 확인
- 3종 칩이 실제 상태를 반영하는지 확인 — 점검 전 "확인 전", 권한 거부 시 "마이크 권한 차단됨"
- 카메라 없음 시 카메라 칩만 경고로 표시되고 마이크(입력 감지 후)·권한 칩은 정상인지 확인

### 성능 요구사항

- 없음

### 인터페이스 요구사항

- 레벨 측정: `livekit-client`의 `createAudioAnalyser` (Web Audio 직접 사용 없음)
- 레벨 바에 접근성 role(meter)과 현재 값을 제공한다

- 미리보기 `<video>`는 음소거(muted)로 재생한다 — 자기 목소리 에코 방지.

### 기타 요구사항

## 장치 선택·전환·상실 처리

### 설명

연결된 장치 목록을 보여주고 점검 중 장치를 바꿀 수 있게 하며, 전환 실패와 사용 중 장치 상실 시의 동작을 정의한다.

- 장치 선택 UI는 **커스텀 드롭다운**이다(네이티브 select는 열린 채로 목록을 갱신할 수 없음). 점검 전에도 활성 상태로 자리 표시("기본 카메라"/"기본 마이크")를 보여주고, **클릭하면 점검(권한 요청)을 시작**해 메뉴 안에 "장비 연결 중"을 표시한 뒤 목록으로 전환한다.
- 장치 목록(카메라·마이크)은 **권한 획득 후** 로드한다 — 획득 전에는 브라우저가 라벨을 비워 보내므로 목록을 미리 보여줄 수 없다.
- 장치를 선택하면 기존 `LocalTrack` 객체를 유지한 채 **내부 MediaStreamTrack을 선택한 장치로 재획득**한다(`setDeviceId` — 새 LocalTrack을 만들지 않을 뿐, 내부 미디어 트랙은 기존 것을 중지하고 교체한다). 미리보기·레벨 미터가 즉시 따라간다.
- 점검 중 장치가 꽂히거나 빠지면(`devicechange`) 목록을 갱신한다.
- **전환 실패 처리**: 전환이 진행되는 동안 해당 select를 비활성(로딩)한다. `setDeviceId`는 내부 미디어 트랙을 **먼저 중지한 뒤** 새 장치를 획득하므로, 전환 실패 시 기존 트랙도 이미 종료됐을 수 있다. 따라서 실패 시 안내를 표시하고 **이전 장치 또는 기본 장치의 재획득을 시도**하며, 결과는 장치 종류별로 다르게 처리한다:
  - **마이크 전환 실패**: 복구에 성공하면 점검 완료 상태를 유지하고, 복구까지 실패하면 점검을 무효화하고 "면접 시작"을 비활성화한다.
  - **카메라 전환 실패**: 복구에 성공하면 미리보기를 유지하고, 복구까지 실패하면 "카메라 사용 불가" 상태로 전환하되 음성 면접은 계속 허용한다(시작 활성 유지).
  - 선택 장치 ID는 **최초 전환 또는 복구가 성공한 장치의 ID로 갱신**하므로 select는 항상 실제 사용 중인 장치를 가리킨다.
- **장치 상실 처리** — 사용 중 트랙의 `ended` 이벤트와 `devicechange` 목록 대조로 감지한다:
  - **마이크 제거**: 남은 마이크가 있으면 **기본 마이크로 자동 전환**하고 전환 안내를 표시한다(점검 완료 유지). 기본 마이크는 남은 장치 중 `deviceId === "default"`를 우선 사용하고, 없으면 열거된 첫 번째 마이크를 사용한다. 남은 마이크가 없거나 자동 전환도 실패하면 **점검을 무효화**하고 "면접 시작"을 비활성화한다("마이크 연결이 끊겼어요 — 다시 점검" 안내).
  - **카메라 제거**: "카메라 사용 불가" 경고로 전환하되 면접 시작은 계속 허용한다(음성 진행).

### 실행 조건

- 장비 점검 시작(기능 1) 성공이 선행되어야 한다.

### 검증 기준

- 점검 완료 후 select에 실제 장치 라벨이 표시되는지 확인
- 마이크 전환 시 레벨 미터가 새 장치 입력을 따르는지 확인
- 카메라 전환 시 미리보기가 교체되는지 확인
- 점검 중 장치를 연결하면 목록에 나타나는지 확인
- 장치 전환 실패 시 안내가 표시되고 select가 실제 사용 중인 장치로 복구되는지 확인
- 전환 실패 후 이전 또는 기본 마이크 재획득에 성공하면 점검 완료가 유지되는지 확인
- 마이크 전환과 복구가 모두 실패하면 점검이 무효화되고 "면접 시작"이 비활성화되는지 확인
- 카메라 전환과 복구가 모두 실패하면 카메라 경고가 표시되지만 면접 시작은 계속 활성화되는지 확인
- 사용 중 마이크 제거 시 남은 마이크로 자동 전환되고 안내가 표시되는지 확인
- 마이크가 모두 제거되면 점검이 무효화되고 "면접 시작"이 비활성화되는지 확인
- 사용 중 카메라 제거 시 경고로 전환되고 면접 시작은 유지되는지 확인

### 성능 요구사항

- 없음

### 인터페이스 요구사항

- select에 aria-label("카메라 선택"/"마이크 선택")을 제공한다

### 제약사항

## 면접 시작 게이팅·핸드오프

### 설명

점검 결과를 면접 시작 조건과 면접 화면 설정에 연결한다.

- **게이팅**: "면접 시작"은 **마이크 트랙 확보 + 실입력 감지 + 전환·복구 중 아님**일 때만 활성화한다. 점검 전에는 "장비 점검을 완료하면 면접을 시작할 수 있어요", 점검 후 입력 대기 중에는 "마이크에 대고 말해 입력을 확인해 주세요" 안내를 표시한다. **카메라는 시작 조건이 아니다** — 없으면 경고만 표시하고 시작을 허용한다.
- **핸드오프**: "면접 시작" 클릭 시 **선택한 마이크(micId)만** sessionStorage에 저장하고 `/live`로 이동한다. `/live`의 `useLiveKitRoom`이 Room 생성 시 저장된 micId를 `audioCaptureDefaults.deviceId`로 적용해, 점검에서 고른 마이크로 면접을 진행한다. 카메라는 `/live`에서 아직 사용하지 않으므로 저장하지 않는다 — 면접 중 self-view 연동(후속 과제) 시 스키마를 확장한다.
- 저장 실패(시크릿 모드 쿼터 등) 시에도 차단하지 않는다 — 기본 장치로 면접 진행 가능.
- **setup→live 사이 저장된 마이크가 제거된 경우**: 저장값이 문법상 정상이어도 장치가 이미 사라졌을 수 있다. `/live`에서 마이크를 켜는 동작이 `NotFoundError`·`OverconstrainedError`로 실패하면 **저장값을 제거하고 기본 마이크를 명시적으로 지정해 1회 재시도**한다 — 이미 생성된 Room의 캡처 기본값은 저장값 삭제만으로 바뀌지 않으므로 재시도 호출에 기본 장치를 직접 전달해야 한다. 재시도까지 실패하거나 `NotAllowedError` 등 다른 원인이면 기존 실패 안내를 유지한다(재시도 없음).

### 실행 조건

- 장비 점검 시작(기능 1) 성공이 선행되어야 한다.

### 검증 기준

- 점검 전 "면접 시작"이 비활성화되고 안내가 표시되는지 확인
- 점검 후에도 마이크 입력이 감지되기 전에는 활성화되지 않고 "말해 주세요" 안내가 표시되는지 확인
- 마이크 입력 감지 시 활성화되는지 확인 — 카메라가 없어도 활성화
- 면접 화면에서 setup에서 고른 마이크로 발행되는지 확인 (Room 캡처 기본값 적용)
- 저장된 마이크가 이미 제거된 상태에서 마이크를 켜면 저장값이 제거되고 기본 마이크로 1회 재시도되는지 확인 (권한 오류는 재시도 없이 기존 안내 유지)
- 같은 탭 새로고침 후 저장값이 유지되는지 확인
- 탭별 저장값 변경이 다른 탭에 동기화되지 않는지 확인
- 저장값이 없거나 손상돼도 기본 마이크로 면접이 진행되는지 확인

### 성능 요구사항

- 없음

### 인터페이스 요구사항

- 모듈: `src/hooks/devicePreferences.ts` (save/load), `src/hooks/useLiveKitRoom.ts` (Room 생성 옵션 적용)

### 제약사항

- 룸 연결 전 마이크 버퍼링(pre-connect audio buffer)은 이 스토리 범위 밖 — `/live` 연결 개선 후속 과제로 남긴다.
