# 면접 종료 (FE)

> **스토리**: HBB1-294 — 나는 사용자로서 면접을 정상적으로 끝낼 수 있다.
>
> **원천 문서**: 종료 계약의 원천은 Kkori-Backend `docs/requirements/session/interview-session-completion.md`(확정)이다 — 상태 머신·webhook·fallback 등 서버 동작은 그 문서가 정의하고, **이 문서는 FE 화면 동작만** 정의한다.
>
> **계약 상태**: 종료 API는 **백엔드 스토리 브랜치 구현 완료 — develop 머지 대기**(BE HBB1-295~297). FE 생성물(orval)은 해당 브랜치 스펙으로 재생성했다.

## Overview

면접 진행 화면(`/live`)의 "면접 종료"를 실계약으로 재배선하고, 종료 감지와 완료 화면을 붙인다. 서버 계약은 비동기다 — `POST /api/v1/sessions/{id}/end`의 202는 "수리"이고, 룸 소멸은 이후 `Disconnected(ROOM_DELETED)`로 도착한다.

> **2026-08-10 갱신 (HBB1-308과 병행한 제품 결정)**: 버튼 종료는 클로징 발화를 기다리지 않는다 — FE는 **202 수리(또는 S008)를 종료 확정으로 보고 즉시 완료 화면으로 전환**한다. 202가 서버의 terminal 수렴(fallback 최대 180초)을 보장하므로 대기 없이 떠나도 안전하다. ROOM_DELETED 는 시간 만료 자연 종료·서버 삭제 경로의 수렴점으로 유지된다.

```text
"면접 종료" 클릭 ──▶ 확인 모달 ──▶ POST /api/v1/sessions/{id}/end (202 수리)
    │                                └─▶ 즉시 저장값 정리 → /live/ended (완료 안내 + 대시보드 이동)
    ├─ 시간 만료 자연 종료 ──┐
    └─ 서버 fallback 삭제 ──┤──▶ Disconnected(ROOM_DELETED) ──▶ 저장값 정리 → /live/ended
그 외 사유의 disconnect ──▶ 재입장 오버레이 (HBB1-308 — interview-reconnect.md)
```

### 기능 요구사항

| No. | Function           | Description                                                                                              |
| --- | ------------------ | -------------------------------------------------------------------------------------------------------- |
| 1   | 종료 요청          | "면접 종료" 클릭 시 확인 모달을 거쳐 종료 API를 호출하고, 수리(202·S008) 즉시 완료 화면으로 전환한다.         |
| 2   | 종료 감지·화면 전환 | 자연 종료(시간 만료·서버 삭제)는 `DisconnectReason === ROOM_DELETED`로 판정해 완료 화면으로 전환한다.        |
| 3   | 종료 완료 화면     | 완료 안내와 대시보드 이동 버튼을 제공한다. 종료 흐름 없이 직행하면 대시보드로 돌려보낸다.                     |

## 종료 요청

### 설명

- **계약** — `POST /api/v1/sessions/{id}/end`(인증 Bearer) → 202 `{ success: true, data: null }`. `id`는 세션 핸드오프 레코드(`hbb.interview.session`)의 세션 id. **멱등** — 이미 종료된 세션에 재호출해도 202 no-op이며, terminal 세션의 재호출은 잔존 룸 삭제를 재시도하는 **설계된 복구 경로**다(룸이 안 닫히고 지속되면 재호출이 올바른 행동).
- **확인 모달**(DS Modal): "면접을 종료할까요?" — 종료 후 재개 불가를 안내하고, 확정 시에만 호출한다.
- **즉시 전환** (2026-08-10 갱신): 202 수리를 종료 확정으로 보고 저장값을 정리한 뒤 즉시 완료 화면으로 이동한다 — 클로징 발화를 기다리지 않으며, 화면 이탈(언마운트)이 연결 해제를 겸한다. 요청 진행 중에는 종료 버튼을 "종료 중…"으로 비활성화한다.
- **에러 처리**: `S008`(500, 종료 신호 발신 실패)은 종료 의도가 이미 기록된 상태 — 서버 fallback이 최대 180초 내 룸 종료를 보장하므로 **202와 동일하게 즉시 완료 화면으로 수렴**한다. `S006`(404)·`S007`(403)은 정상 흐름에서 도달하지 않는다(자기 세션 id 사용) — 그 외 코드와 함께 공통 실패 안내 + 명시 재시도 버튼 + 서버 메시지 병기로 처리한다. 자동 재시도는 두지 않는다.

### 검증 기준

- 종료 확정 시 `/end`가 세션 id로 1회 호출되고, 202 수리 즉시 저장값 정리와 완료 화면 전환이 일어나는지 확인
- 모달에서 계속하기를 누르면 호출이 발생하지 않는지 확인
- S008도 202와 동일하게 즉시 완료 화면으로 수렴하는지 확인 (그 외 실패는 안내 + 재시도 유지)

## 종료 감지·완료 화면

### 설명

- **자연 종료 수렴점**: LiveKit `Disconnected` 이벤트의 `DisconnectReason === ROOM_DELETED`가 자연 종료(시간 만료·서버 fallback 삭제)의 "면접 종료" 신호다. 버튼 종료는 202 확정 즉시 전환하므로(2026-08-10 갱신) 이 신호를 기다리지 않는다.
- **전환**: ROOM_DELETED 수신 또는 종료 확정(202·S008) 시 세션 저장값(`hbb.interview.session`)을 정리하고(죽은 룸 토큰 — `/live` 재진입이 setup으로 가게) `/live/ended`로 replace 이동한다. 정당 진입 표식은 이동 state(`{ ended: true }`)로 전달한다. 종료 확정 수렴은 연결 유무와 무관하다 — 구 "연결 없는 종료의 수렴" 규칙(202 한정, 연결 없음 조건)은 이 일반화로 대체됐다.
- **그 외 사유의 disconnect**는 재입장 오버레이(HBB1-308 — interview-reconnect.md)가 받는다. 오버레이에서도 종료 버튼은 살아 있어 사용자의 출구가 된다.
- **완료 화면**(`/live/ended`, protected): 완료 안내("면접이 끝났어요" + 리포트 예고 문구)와 대시보드 이동 버튼만 제공한다. 리포트 대기·조회 연계는 리포트 스토리 소관(문구·버튼까지만). 종료 흐름 표식이 없는 진입(새 탭·직접 URL 입력)은 대시보드로 replace 리다이렉트한다 — 완료 화면에서의 새로고침은 히스토리 state 가 유지되어 완료 화면이 그대로 남는다(브라우저 동작, 실검증 확인).
- **타이머 표시 제거**: 기존 "04:12 남음" 칩은 하드코딩 목이었고, 남은 시간의 원천이 서버에 없어 어림값 표기가 오정보라 제거했다. 자연 만료는 ROOM_DELETED 수렴으로 처리되므로 기능상 공백이 없다 — 실카운트다운은 서버가 기준시를 제공하게 될 때 별도 검토.

### 검증 기준

- `/end` 없이 도착한 ROOM_DELETED(자연 종료) 해제 시 저장값이 제거되고 완료 화면으로 전환되는지 확인
- 그 외 사유의 해제는 종료로 전환하지 않고 재입장 오버레이가 뜨며 저장값이 남는지 확인 (interview-reconnect.md)
- 이미 끊긴 상태의 종료도 202 수리 즉시 완료 화면에 수렴하는지 확인 (연결 유무 무관)
- 완료 화면에서 대시보드 이동이 동작하고, 종료 표식 없는 직행이 대시보드로 리다이렉트되는지 확인

## 인터페이스 요구사항

- 클라이언트: `src/api/client.ts` — `endInterviewSession(sessionId)` = orval 생성 `end` fetcher 위임. 훅: `src/api/hooks.ts` — `useEndInterviewSession`(useMutation, 자동 재시도 없음)
- 에러 코드: `src/api/errorCodes.ts` — `S006`·`S007`·`S008` (세션 생성 계열 S001~S005에 이어 추가)
- LiveKit: `src/hooks/useLiveKitRoom.ts` — `disconnectReason: DisconnectReason | null` 노출 (Room이 속성으로 제공하지 않아 `Disconnected` 이벤트 인자를 상태로 보존)
- 라우트: `src/routes.ts` — `interviewEnded: "/live/ended"`(protected), 화면 `src/pages/InterviewEndedPage.tsx`

## 제약사항·범위 외

- 리포트 대기·조회 연계(완료 화면의 문구·버튼만), 재연결·네트워크 복구(INTERRUPTED)·rejoin은 범위 외 — 후속 스토리.
- AI 면접관의 클로징 발화·룸 삭제는 Kkori-AI/BE 소관 — FE는 신호 수신만 한다. 로컬(에이전트 미접속, PENDING)에서는 `/end`가 룸을 즉시 삭제해 동일 신호로 수렴한다.
