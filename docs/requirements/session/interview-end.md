# 면접 종료 (FE)

> **스토리**: HBB1-294 — 나는 사용자로서 면접을 정상적으로 끝낼 수 있다.
>
> **원천 문서**: 종료 계약의 원천은 Kkori-Backend `docs/requirements/session/interview-session-completion.md`(확정)이다 — 상태 머신·webhook·fallback 등 서버 동작은 그 문서가 정의하고, **이 문서는 FE 화면 동작만** 정의한다.
>
> **계약 상태**: 종료 API는 **백엔드 스토리 브랜치 구현 완료 — develop 머지 대기**(BE HBB1-295~297). FE 생성물(orval)은 해당 브랜치 스펙으로 재생성했다.

## Overview

면접 진행 화면(`/live`)의 "면접 종료"를 실계약으로 재배선하고, 종료 감지와 완료 화면을 붙인다. 핵심은 **종료가 비동기 계약**이라는 것 — `POST /api/v1/sessions/{id}/end`의 202는 "수리"일 뿐이고, 실제 종료는 면접관(AI)이 클로징 인사를 말한 뒤 스스로 룸을 삭제할 때 LiveKit `Disconnected(ROOM_DELETED)`로 도착한다.

```text
"면접 종료" 클릭 ──▶ 확인 모달 ──▶ POST /api/v1/sessions/{id}/end (202 수리)
    │                                └─ "면접 마무리 중" — disconnect 하지 않음 (클로징 발화 재생)
    ├─ 시간 만료 자연 종료 ──┐
    ├─ 서버 fallback 삭제 ──┤──▶ Disconnected(ROOM_DELETED) ← 종료 감지의 단일 수렴점
    └─ 버튼 종료         ──┘         └─▶ 저장값 정리 → /live/ended (완료 안내 + 대시보드 이동)
그 외 사유의 disconnect ──▶ 기존 "연결 끊김" 표시 유지 (재연결 UX 는 후속 INTERRUPTED 스토리)
```

### 기능 요구사항

| No. | Function           | Description                                                                                              |
| --- | ------------------ | -------------------------------------------------------------------------------------------------------- |
| 1   | 종료 요청          | "면접 종료" 클릭 시 확인 모달을 거쳐 종료 API를 호출하고, 수리 후 "마무리 중" 상태로 대기한다.               |
| 2   | 종료 감지·화면 전환 | `DisconnectReason === ROOM_DELETED`만 "면접 종료"로 판정해 완료 화면으로 전환한다 — 경로 분기 없음.          |
| 3   | 종료 완료 화면     | 완료 안내와 대시보드 이동 버튼을 제공한다. 종료 흐름 없이 직행하면 대시보드로 돌려보낸다.                     |

## 종료 요청

### 설명

- **계약** — `POST /api/v1/sessions/{id}/end`(인증 Bearer) → 202 `{ success: true, data: null }`. `id`는 세션 핸드오프 레코드(`hbb.interview.session`)의 세션 id. **멱등** — 이미 종료된 세션에 재호출해도 202 no-op이며, terminal 세션의 재호출은 잔존 룸 삭제를 재시도하는 **설계된 복구 경로**다(룸이 안 닫히고 지속되면 재호출이 올바른 행동).
- **확인 모달**(DS Modal): "면접을 종료할까요?" — 종료 후 재개 불가와 마무리 인사 진행을 안내하고, 확정 시에만 호출한다.
- **마무리 중 상태**: 202 수리부터 실제 종료(ROOM_DELETED)까지 종료 버튼을 "면접 마무리 중…"으로 비활성화한다. **이 동안 disconnect 하지 않는다** — 면접관 클로징 발화가 이어서 재생된다. 연결·마이크 발행 상태는 현행 유지.
- **에러 처리**: `S008`(500, 종료 신호 발신 실패)은 종료 의도가 이미 기록된 상태 — 서버 fallback이 최대 180초 내 룸 종료를 보장하므로 **기다려도 안전하다는 지연 안내** + 명시 재시도 버튼(재호출 = 클로징 발화 기회를 되살리는 선택지)을 표시한다. `S006`(404)·`S007`(403)은 정상 흐름에서 도달하지 않는다(자기 세션 id 사용) — 그 외 코드와 함께 공통 실패 안내 + 서버 메시지 병기로 처리한다. 자동 재시도는 두지 않는다.

### 검증 기준

- 종료 확정 시 `/end`가 세션 id로 1회 호출되고, 202 후에도 disconnect 가 발생하지 않은 채 "마무리 중" 상태가 되는지 확인
- 모달에서 계속하기를 누르면 호출이 발생하지 않는지 확인
- S008 실패 시 지연 안내와 재시도 버튼이 표시되고, 재시도의 202(멱등)로 "마무리 중"에 복귀하는지 확인

## 종료 감지·완료 화면

### 설명

- **단일 수렴점**: LiveKit `Disconnected` 이벤트의 `DisconnectReason === ROOM_DELETED`가 "면접 종료"다. 버튼 종료·시간 만료 자연 종료·서버 fallback 삭제가 전부 이 신호로 수렴한다 — `/end`를 누르지 않은 자연 종료에도 동일 적용되며 경로 분기가 없다.
- **전환**: ROOM_DELETED 수신 시 세션 저장값(`hbb.interview.session`)을 정리하고(삭제된 룸 토큰 — `/live` 재진입이 setup으로 가게) `/live/ended`로 replace 이동한다. 정당 진입 표식은 이동 state(`{ ended: true }`)로 전달한다.
- **그 외 사유의 disconnect**(/end 수리 전)는 기존 "연결 끊김" 표시를 유지한다 — 재연결·복구 UX는 후속 INTERRUPTED 스토리 소관. 이때도 종료 버튼은 살아 있어 사용자의 출구가 된다.
- **연결 없는 종료의 수렴**: /end가 수리(202)된 뒤 연결이 없는 상태 — 이미 끊긴 채 종료했거나 마무리 중 다른 사유로 연결을 잃은 경우 — 는 ROOM_DELETED를 더 수신할 수 없다. **202가 서버의 terminal 수렴(fallback 포함)을 보장하므로 종료로 간주해 완료 화면으로 전환**한다 — "마무리 중" 영구 잠금을 만들지 않는다.
- **완료 화면**(`/live/ended`, protected): 완료 안내("면접이 끝났어요" + 리포트 예고 문구)와 대시보드 이동 버튼만 제공한다. 리포트 대기·조회 연계는 리포트 스토리 소관(문구·버튼까지만). 종료 흐름 표식이 없는 진입(새 탭·직접 URL 입력)은 대시보드로 replace 리다이렉트한다 — 완료 화면에서의 새로고침은 히스토리 state 가 유지되어 완료 화면이 그대로 남는다(브라우저 동작, 실검증 확인).
- **타이머 표시 제거**: 기존 "04:12 남음" 칩은 하드코딩 목이었고, 남은 시간의 원천이 서버에 없어 어림값 표기가 오정보라 제거했다. 자연 만료는 ROOM_DELETED 수렴으로 처리되므로 기능상 공백이 없다 — 실카운트다운은 서버가 기준시를 제공하게 될 때 별도 검토.

### 검증 기준

- ROOM_DELETED 해제 시 저장값이 제거되고 완료 화면으로 전환되는지 확인 (버튼 종료 경로·`/end` 없는 자연 종료 경로 동일)
- 그 외 사유의 해제(/end 수리 전)는 전환 없이 "연결 끊김" 표시가 유지되고 저장값이 남는지 확인
- 이미 끊긴 상태의 종료·마무리 중 연결 상실이 202 수리를 근거로 완료 화면에 수렴하는지 확인 (영구 "마무리 중" 잠금 없음)
- 완료 화면에서 대시보드 이동이 동작하고, 종료 표식 없는 직행이 대시보드로 리다이렉트되는지 확인

## 인터페이스 요구사항

- 클라이언트: `src/api/client.ts` — `endInterviewSession(sessionId)` = orval 생성 `end` fetcher 위임. 훅: `src/api/hooks.ts` — `useEndInterviewSession`(useMutation, 자동 재시도 없음)
- 에러 코드: `src/api/errorCodes.ts` — `S006`·`S007`·`S008` (세션 생성 계열 S001~S005에 이어 추가)
- LiveKit: `src/hooks/useLiveKitRoom.ts` — `disconnectReason: DisconnectReason | null` 노출 (Room이 속성으로 제공하지 않아 `Disconnected` 이벤트 인자를 상태로 보존)
- 라우트: `src/routes.ts` — `interviewEnded: "/live/ended"`(protected), 화면 `src/pages/InterviewEndedPage.tsx`

## 제약사항·범위 외

- 리포트 대기·조회 연계(완료 화면의 문구·버튼만), 재연결·네트워크 복구(INTERRUPTED)·rejoin은 범위 외 — 후속 스토리.
- AI 면접관의 클로징 발화·룸 삭제는 Kkori-AI/BE 소관 — FE는 신호 수신만 한다. 로컬(에이전트 미접속, PENDING)에서는 `/end`가 룸을 즉시 삭제해 동일 신호로 수렴한다.
